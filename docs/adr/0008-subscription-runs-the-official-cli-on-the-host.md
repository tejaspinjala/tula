# A subscription provider runs the official `claude` CLI on the host; Claude Code is not the in-sandbox worker yet

On a `subscription` provider (ADR-0005), the model gateway runs the unmodified `claude -p` binary on the Guild Master's Mac. It runs with no tools, no MCP, no user settings and the gateway's own system prompt, and it uses the Guild Master's own signed-in plan. Guildhall never reads, stores or forwards the OAuth token. Anthropic forbids third parties to collect or intermediate claude.ai credentials, and proxies that reused a Max token outside the official client were cut off on 2026-04-04. `claude -p` on your own plan is explicitly supported and draws from that plan's limits. Because the gateway stays the only path to a model, Bar the Gates, caps, private routing and token metering all still apply. Sandboxes keep holding only a run token and a lease. The subscription is disabled by default (`SUBSCRIPTION_PROVIDER`), so a hosted v2 deployment can never route through it.

Running Claude Code itself as the agent inside the sandbox (#15) is deferred. On a subscription, that would put the OAuth token in the container or make the gateway intermediate it, and neither is allowed. With an `api_key` provider it is viable, via an Anthropic Messages passthrough on the gateway (`ANTHROPIC_BASE_URL` set to the gateway, `ANTHROPIC_AUTH_TOKEN` set to the run token), with built-in web tools disabled and MCP set to Guildhall's lease. Revisit it when an `api_key` provider or a v2 deployment needs an agentic harness richer than the governed worker loop.
