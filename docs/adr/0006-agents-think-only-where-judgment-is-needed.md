# Agents think only where judgment is needed

To keep cost per accepted result low, a routine Quest costs one Member run plus whatever verification its action class requires. Hall, rank and data class come from the Quest's template or Rite as data; only free-text goals from the Guild Master go to a cheap-model classifier, whose decisions are logged for the future Oracle. Steward, Officer and Captain are roles in data with deterministic routing, leasing and dispatch, and become LLM calls only for judgment: splitting a goal into Quests, issuing a Verdict, chairing a meeting. Verification is tiered by action class: content bound for a Seal gets deterministic checks with the Guild Master's Seal as judge, while code, deploy and spend Proposals get the full pipeline (fresh verifier, cross-model-family judge). The Council of Elders is not built until autonomy (away mode) exists, since every external action in the first slice needs a Seal.

We rejected having every hierarchy layer run as an LLM agent per Quest, which is closer to the fantasy but multiplies tokens roughly by the number of layers without adding judgment.
